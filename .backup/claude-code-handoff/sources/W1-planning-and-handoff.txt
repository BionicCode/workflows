A **new task inside the same project provides sufficient process isolation**, provided the review prompt requires a fresh repository-state resolution and forbids relying on the earlier task’s conclusions.

The reviewer may still have access to project instructions, files, and possibly useful project context. That is not inherently harmful. Independent review means independently verifying the current diff and evidence—not necessarily forgetting that the earlier work happened.

Moving the acceptance review outside the project would create stronger contextual separation, but it also removes helpful project framing and increases the chance that the reviewer misses repository-specific decisions. I would keep both tasks in the Workflows project:

- **Task 1:** implement the accepted backlog findings.
- **Task 2:** independently review the resulting repository state.

Use `/memories use off` in the acceptance-review task as an additional safeguard. I cannot verify from official documentation that this guarantees removal of all project-level context, so the prompt should enforce evidence-based independence regardless.
